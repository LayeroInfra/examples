# Полка — файлы на Layero Storage

Приватная полка файлов с публичными ссылками. Загрузить, найти, поделиться
ссылкой на час, выложить на витрину, удалить.

Это не витрина возможностей, а рабочая вещь: место, куда кидают скриншот или
PDF и отдают ссылку. И одновременно — приёмка Layero Storage: пример проходит
по всем швам разом (вход, права на строку, байты, подписанные ссылки,
публичная раздача, пределы) и делает это **чужим клиентом**.

```bash
cd storage-shelf
npx layero@latest deploy
```

## Чем интересен

**Клиент — неправленый `@supabase/supabase-js`.** Ни обёрток, ни своего
HTTP-слоя: `createClient(url, key).storage.from('shelf').upload(...)`. Если он
работает против `layero.app`, значит совместимость настоящая, а не заявленная.

**Приложение не проверяет права.** Ни строчки «а свой ли это файл» в
JavaScript нет: код в браузере читает и правит любой посетитель. Кто что
может — решают политики RLS в `schema.sql`, и решают в базе.

**В браузере только публичный ключ.** Секретного здесь нет и быть не может:
сборка фронтенда видит весь env, а бандл читает кто угодно.

## Что показано

| Что | Где смотреть | Почему так |
|---|---|---|
| Загрузка (в том числе перетаскиванием) | `shelf.js` → `upload` | `FormData` из браузера — родная форма их клиента |
| Приватность по папкам | `schema.sql`, политики «полка: …» | первый сегмент пути = `auth.uid()` |
| Ссылка на час | `shelf.js` → `shareLink` | делиться приватным, не делая файл публичным |
| Публикация | `shelf.js` → `publish` | копия в публичный бакет, а не «снять галочку» |
| Раздача без ключа | витрина, `getPublicUrl` | `<img src>` приходит без заголовков |
| Потолок на файл | `schema.sql`, `file_size_limit` | 20 МБ, проверяется до чтения тела |

## Порядок настройки

1. **База.** Панель → «Базы данных» → создать. Включить **API**,
   **Авторизацию** и **Хранилище** — три переключателя, каждый одним нажатием.
2. **Подключить базу к проекту.** После этого платформа сама подставляет в
   сборку `VITE_LAYERO_DATA_URL` и `VITE_LAYERO_DATA_KEY`; в исходниках ключа
   нет.
3. **Политики.** Выполнить `schema.sql` в редакторе запросов панели. Он
   заводит два бакета и семь политик; повторный запуск безопасен.
4. **Домен приложения — в CORS базы.** Иначе браузер отобьёт первый же запрос
   как «Failed to fetch», и выглядеть это будет поломкой платформы, а не
   пропущенной настройкой.
5. `npx layero@latest deploy`.

Локально: положите `.env.local` с теми же двумя переменными и `npm run dev`.

## Чего этот пример НЕ делает

- **не жмёт и не пережимает картинки.** Преобразований у Layero Storage нет
  осознанно, и пример их не имитирует: загруженное отдаётся как есть;
- **не показывает чужие приватные файлы даже владельцу приложения.** Панель
  администратора потребовала бы секретного ключа, то есть сервера;
- **не ограничивает витрину модерацией.** Опубликовать может любой вошедший —
  для настоящей витрины сюда нужна колонка «одобрено» и политика по ней;
- **не переживает смену id пользователя.** Папка названа его id: удалите
  учётку — файлы осиротеют. Это цена простоты, а не недосмотр.

## Проверить, что политика правда работает

Политику легко написать так, что она выглядит рабочей и открыта всем.
Единственная честная проверка — попробовать чужим: зайдите вторым
пользователем и попробуйте прочитать папку первого. Ожидается пустой список и
«Object not found», а не отказ по правам: политика не различает «нет прав» и
«нет файла», и не должна — разница между ними это оракул, отвечающий
перебирающему «здесь что-то есть».

Пошагово — в конце `schema.sql`.
